# YYAbroad 产品需求文档（PRD）

## 1. 产品简介

YYAbroad 是一个面向留学申请学生的智能 Agent。

它不只是回答留学问题，而是长期了解学生情况，帮助学生完成选校、申请规划、材料准备和进度管理，并通过学校官网、邮箱、日历和申请系统等外部工具持续跟进申请。

产品核心流程：

> 了解学生 → 明确目标 → 搜索项目 → 制定选校方案 → 规划材料 → 生成申请计划 → 跟进申请进度

### 1.1 产品形态

- 第一版做成可在线访问的响应式 Web App。
- P0 内部测试版不做注册登录，使用单用户测试空间验证核心功能。
- 公开测试前再加入账号体系，用于保存学生画像、选校清单、申请材料和任务进度。
- 支持电脑和手机浏览器访问，第一版不开发原生客户端。
- 学校申请网站自动填写后续通过浏览器插件实现。

## 2. 目标用户

- 正在准备本科或硕士留学申请的学生。
- 不清楚自己适合哪些学校和专业的学生。
- 同时申请多个项目，需要管理材料和截止日期的学生。
- 希望自己申请，但需要智能规划和辅助的学生。

首个版本建议优先服务申请海外硕士项目的中国学生。

### 3.1 申请材料规划与选择

Agent 根据不同学校和项目的要求，帮助学生确定“需要准备什么、应该使用哪些经历、最终提交哪个文件版本”。

CV（个人简历）和 PS（个人陈述）是两类独立的申请材料。系统分别保存、编辑和管理它们，材料规划 Agent 负责根据不同项目协调两类材料的内容重点和提交版本。

具体功能包括：

- 从学校官网提取简历、文书、成绩单、推荐信、作品集等材料要求。
- 为每个申请项目生成独立的材料清单，标记必交、选交、待确认和已完成状态。
- 从学生的科研、实习、课程、竞赛和项目经历中，选择与目标专业最相关的素材。
- 为 CV 选择需要保留的经历，建议经历顺序、篇幅和表达重点。
- 为 PS 解析学校题目，选择适合的个人经历并建议文章结构和叙事重点。
- 根据不同学校和项目分别生成 CV、PS 定制方案。
- 判断现有材料是否缺少关键证明、先修课程说明或补充文件。
- 管理通用版本、学校定制版本和已提交版本。
- 在上传前推荐正确文件，并检查学校、项目、语言、日期和版本是否匹配。
- 解释选择或排除某项素材的原因，不替学生编造经历和证明。

最终输出包括：项目材料清单、推荐经历组合、材料缺口、文件版本建议和提交前检查结果。

#### CV：个人简历（Curriculum Vitae）

- 从经历库选择与目标项目最相关的教育、科研、实习和项目经历。
- 建议内容顺序、篇幅和需要量化的成果。
- 检查日期、职位、成绩和项目描述是否与其他材料一致。
- 为不同学校生成对应版本，但不得编造经历或成果。

#### PS：个人陈述（Personal Statement）

- PS 至少绑定一个目标专业方向，不设置跨专业通用稿；CS、DS 等相近专业也分别管理专业方向版本。
- 专业方向 PS 只作为基础稿和素材来源，不能直接视为任一学校项目的可提交版本。
- 解析学校的 PS 题目、字数和内容要求。
- 从经历库中选择能够支持申请动机、能力和目标的真实素材。
- 生成文书提纲、素材安排和学校定制建议。
- 检查是否回答题目、是否误用其他学校名称以及是否存在空泛内容。
- AI 提供结构和修改建议，最终内容由学生确认。

## 4. 主要页面

### 4.1 今日工作台

- 今天最重要的任务。
- 临近的申请截止日期。
- 当前申请风险。
- 需要学生确认的 Agent 操作。

### 4.2 我的画像

- 学术背景和成绩。
- 实习、科研和项目经历。
- 申请目标、预算和偏好。
- 信息来源和修改记录。

### 4.3 项目探索

- 使用自然语言搜索学校和项目。
- 查看项目要求和官方来源。
- 比较项目并加入选校清单。

### 4.4 申请看板

- 每个项目的申请状态。
- 截止日期和材料完成情况。
- 推荐信、面试和 Offer 状态。

### 4.5 材料中心

- 每个项目的材料清单和完成状态。
- Agent 推荐的经历素材及选择原因。
- CV（个人简历）：经历选择、排序、修改建议和学校定制版本。
- PS（个人陈述）：题目解析、素材选择、提纲和学校定制版本。
- 成绩单、推荐信和其他补充材料。
- 通用版本和学校定制版本。
- AI 修改建议和材料检查结果。

## 5. 外部工具与 Agent 功能

### 5.1 学校官网工具

Agent 可以：

- 搜索学校和项目官网。
- 读取申请要求、费用和截止日期。
- 定期检查官网信息是否发生变化。
- 保存信息来源和最后核验时间。

### 5.2 申请网站助手

在学生已经登录的情况下，Agent 可以：

- 读取当前申请状态和缺少的材料。
- 根据学生档案预填重复信息。
- 选择需要上传的材料版本。
- 检查必填字段和未完成页面。
- 提交前生成完整检查清单。

验证码、电子签名、最终提交和付款必须由学生完成或确认。

### 5.3 邮箱监控 Agent

连接学生授权的邮箱后，Agent 可以：

- 识别申请确认、补件、面试、Offer 和拒信邮件。
- 提取学校、项目、截止日期和需要完成的操作。
- 自动关联到对应申请项目。
- 创建任务和提醒。
- 生成回复邮件草稿。

Agent 默认不能自动发送、删除或转发邮件。

### 5.4 日历工具

- 创建考试、面试和申请截止日程。
- 自动转换学校和学生所在地时区。
- 检查考试、课程和面试冲突。
- 截止日期变化后调整相关任务。

### 5.5 材料规划与选择 Agent

材料规划与选择 Agent 结合学校官网要求、学生画像和已有文件，为每个申请项目生成对应的材料方案。

Agent 可以：

- 读取官网要求，生成项目材料清单。
- 从学生的科研、实习、课程和项目经历中选择相关素材。
- 为 CV 推荐需要保留的经历、排序和表达重点。
- 为 PS 解析题目、选择真实素材并生成叙事提纲。
- 根据不同项目生成对应的 CV 和 PS 定制方案。
- 判断学生还缺少哪些证明、成绩、推荐信或补充材料。
- 调用云盘工具查找适合该项目的文件版本。
- 上传前检查文件是否属于正确的学校、项目和申请轮次。
- 说明材料选择理由，并将低置信度选择交给学生确认。

Agent 只提供材料方案和选择建议，不得编造经历、修改成绩或未经确认上传文件。

### 5.6 云盘和文件工具

- 读取学生授权目录中的申请材料。
- 识别简历、成绩单、文书和 Offer。
- 管理通用版本、学校版本和已提交版本。
- 上传前检查是否选错文件。

### 5.7 主动提醒 Agent

以下事件可以主动触发 Agent：

- 收到新的申请邮件。
- 官网修改了截止日期或申请要求。
- 距离截止日期很近，但材料没有完成。
- 推荐信长时间没有提交。
- 学生成绩或申请目标发生变化。
- 收到面试邀请或 Offer。

## 6. AI 技术能力

| 技术能力 | 使用场景 |
|---|---|
| 大语言模型 | 对话、分析、解释、计划和内容反馈 |
| Tool Calling | 调用搜索、邮箱、日历、云盘和浏览器工具 |
| RAG | 根据学校官网和学生材料回答问题 |
| OCR 与多模态模型 | 读取成绩单、简历、Offer 和网页截图 |
| Embedding 与向量检索 | 项目搜索、经历匹配和材料检索 |
| 规则引擎 | 判断硬性申请要求、日期和材料完整性 |
| 长期记忆 | 保存学生画像、偏好、申请状态和历史决策 |
| Agent 工作流 | 拆解任务、执行工具、等待确认和持续跟进 |
| 评测与监控 | 检查幻觉、错误引用、工具失败和执行成本 |

大模型负责理解、推理和解释；数据库、规则引擎和工具负责保存事实、计算日期和执行操作。

## 7. 权限与安全

| 操作类型 | 示例 | 处理方式 |
|---|---|---|
| 公开信息读取 | 搜索和读取学校官网 | Agent 可以自动执行 |
| 私人信息读取 | 读取邮箱、日历和云盘 | 需要用户授权 |
| 内部操作 | 创建任务、生成草稿 | 可以自动创建，允许用户修改 |
| 外部操作 | 预填网页、创建日程 | 执行前展示内容 |
| 高风险操作 | 发邮件、提交申请、付款、接受 Offer | 每次必须由用户明确确认 |

其他安全要求：

- 优先使用 OAuth，不保存用户邮箱密码。
- 只申请完成任务所需的最小权限。
- 所有外部操作保留日志。
- 工具失败时不得伪造成功结果。
- 防止邮件或网页内容诱导 Agent 越权执行操作。
- 用户可以暂停监控、取消授权和删除数据。

## 8. 需求优先级与实现顺序

### 8.1 P0：形成可用的留学申请闭环

P0 是内部测试版必须完成的功能，目标是优先验证核心产品价值。测试用户不依赖人工顾问，可以完成“建立画像—搜索项目—形成选校清单—规划材料—管理申请”的完整流程。

#### P0-1 核心 Agent 基础

- 单用户测试空间，不实现注册和登录。
- Agent 对话、模型调用和基础工具调用。
- 临时保存学生画像、选校清单和任务状态。
- 简历、成绩单等测试文件上传与解析。
- 基础错误记录和调试日志。
- 少量人工维护的测试项目数据。

#### P0-2 学生画像

- 对话采集教育、成绩、语言、实习、科研、预算和偏好。
- 解析简历和成绩单，提取候选信息。
- 学生确认后保存结构化画像。
- 支持修改、导出和删除个人数据。

#### P0-3 项目搜索与官网核验

- 使用自然语言搜索项目。
- 从学校官网读取申请要求、费用和截止日期。
- 保存来源链接和最后核验时间。
- 无法确认的信息明确标记，不由大模型补成事实。

#### P0-4 智能选校

- 根据学生画像和申请目标筛选项目。
- 给出冲刺、主申和相对稳健的选校建议。
- 展示推荐理由、风险和不满足的硬性要求。
- 支持项目比较、收藏和选校清单管理。

#### P0-5 申请材料规划

- 根据每个项目生成材料清单。
- 分别规划 CV（个人简历）和 PS（个人陈述）。
- 为 CV 选择相关经历并建议内容顺序。
- 为 PS 解析题目、选择真实素材并生成提纲。
- 管理通用版本、学校定制版本和已提交版本。
- 上传前检查学校、项目、语言和文件版本。

#### P0-6 申请时间线与任务管理

- 根据项目截止日期生成申请时间线。
- 管理材料、推荐信、网申和截止日期任务。
- 首页展示今日任务、申请进度和临近风险。
- 允许学生手动更新每个项目的申请状态。

#### P0 完成标准

受邀测试学生可以在单用户测试空间中独立完成一次完整流程：

> 建立画像 → 搜索并核验项目 → 生成选校清单 → 获得 CV/PS 材料方案 → 生成申请任务

P0 可以由受邀测试用户在受控环境中使用，但不面向公众开放长期保存真实敏感材料。

### 8.2 P1：产品化与申请执行增强

P1 在 P0 闭环稳定后实现，重点是将内部原型产品化，并提高材料和申请执行效率。

- 注册、登录、找回账号和退出登录。
- 用户数据隔离、权限控制和隐私授权。
- 学生数据长期保存、导出、删除和账号注销。
- 文件加密存储和基础运营后台。
- CV 深度修改、成果量化和多版本比较。
- PS 长文编辑、题目覆盖检查和学校定制检查。
- CV、PS、成绩单和网申信息一致性检查。
- 邮箱只读监控，识别补件、面试和 Offer 等申请邮件。
- 邮件事件自动关联项目并创建任务。
- 日历连接、时区转换和截止日期提醒。
- 云盘连接与材料文件同步。
- Agent 主动提醒和每周申请进度总结。
- 官网申请要求和截止日期变化监控。

### 8.3 P2：外部执行与完整申请周期

P2 在账号安全、数据准确率和 Agent 工具调用稳定后实现。

- 浏览器插件和申请网站状态读取。
- 根据学生档案预填网申字段。
- 上传材料前自动选择并检查文件版本。
- 面试语音陪练和动态追问。
- Offer 解析、比较和决策辅助。
- 签证、住宿和行前准备。
- 家长、老师或留学顾问协作。

### 8.4 第一版明确不实现

- 自动提交申请。
- 自动支付申请费或押金。
- 未经确认自动发送邮件。
- 自动完成电子签名、诚信声明或验证码。
- 覆盖全球所有国家、学校和专业。

## 9. 产品指标

- 完成学生画像的用户比例。
- 从项目搜索进入选校清单的比例。
- 带官方来源的项目信息覆盖率。
- 官网信息和截止日期的准确率。
- 每名学生每周完成的申请任务数。
- 邮件事件正确关联到申请项目的比例。
- Agent 建议被用户接受的比例。
- 发生重复执行或未经确认操作的次数，目标必须为 0。

## 10. 产品边界

- 不承诺录取结果。
- 不提供虚假的精确录取概率。
- 不编造学生经历、成绩或推荐信内容。
- 不用未经核验的大模型记忆代替学校官方要求。
- 不在没有学生确认的情况下提交申请、付款或发送邮件。
- 签证和移民信息必须引用官方来源，并提示学生最终向官方确认。

## 11. 版本路线图

| 版本 | 优先级 | 主要结果 |
|---|---|---|
| v0.1 内部原型 | P0-1 至 P0-3 | 不做账号，跑通 Agent、学生画像和少量项目搜索 |
| v0.5 MVP | 全部 P0 | 学生可以完成选校、材料规划和申请任务闭环 |
| v1.0 公开测试版 | P1 | 上线账号体系、材料深度辅助、邮箱、日历、云盘和主动提醒 |
| v2.0 Agent 执行版 | P2 | 上线浏览器插件、网申辅助、面试、Offer 和签证功能 |

## 12. 可选认证服务

YYAbroad 提供认证开关，使同一套 Web App 同时支持内部单用户测试和公网多用户服务。

### 12.1 认证开关

| 配置 | 使用方式 | 用户和数据行为 | 适用场景 |
|---|---|---|---|
| 关闭认证 | 访问网址后直接使用 | 所有访问者共享同一个本地管理员身份和同一套数据 | 本机开发、内部受控测试 |
| 开启认证 | 注册或登录后使用 | 每名用户拥有独立身份、数据和申请空间 | 公网测试、正式上线 |

关闭认证不代表匿名用户各自拥有独立空间。任何能够访问部署地址的人都可以使用同一个共享空间，因此关闭认证的实例不得直接暴露在公网。

### 12.2 开启认证后的用户流程

1. 系统不存在用户时，访问者进入首次注册页面。
2. 第一个成功注册的用户自动成为管理员。
3. 管理员创建后，公开自助注册入口关闭。
4. 后续账号由管理员创建，默认角色为普通用户。
5. 管理员可以查看用户列表、禁用账号和调整用户角色。
6. 普通用户只能访问自己的学生画像、材料、选校清单和申请任务。

### 12.3 用户角色

| 角色 | 权限 |
|---|---|
| 本地管理员 | 认证关闭时使用，拥有共享空间的全部权限 |
| 管理员 | 管理用户、系统配置和公共项目数据，也可使用申请功能 |
| 普通用户 | 只能管理自己的画像、材料、选校清单和申请记录 |

### 12.4 功能要求

- 提供统一认证配置开关，修改后重启服务生效。
- 支持注册、登录、退出和登录状态检查。
- 密码只保存安全哈希，不保存明文密码。
- 登录成功后使用安全会话 Cookie 保存登录状态。
- 后端 API 和实时连接使用同一套认证校验。
- 多用户模式下，所有学生数据必须按照用户身份隔离。
- 所有管理员操作保留操作日志。
- 支持管理员创建、禁用和调整用户角色。
- 后续支持找回密码、邮箱验证和第三方登录。

### 12.5 开发优先级

- P0 内部原型：关闭认证，使用单用户测试空间。
- P1 公开测试：实现认证开关、首位管理员注册、管理员创建用户和数据隔离。
- P2 正式运营：增加邮箱验证、找回密码、登录风控和第三方登录。

### 12.6 验收标准

- 关闭认证后无需登录即可进入系统，并始终使用同一个本地管理员空间。
- 开启认证后，未登录用户不能访问受保护页面和 API。
- 第一个注册用户成为管理员，之后公开注册请求被拒绝。
- 管理员可以创建普通用户，普通用户不能进入管理后台。
- 两个普通用户之间不能读取、修改或删除对方的数据和文件。
- 关闭认证的实例如果绑定公网地址，系统必须显示明显的安全警告。
